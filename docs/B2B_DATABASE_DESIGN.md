# BizPilot — B2B Database Design

**Status:** Proposal — no migrations written
**Companion to:** `B2B_ARCHITECTURE.md`

---

## 1. Design principles

1. **Smallest robust model.** Every table must support an approved workflow. No
   speculative tables.
2. **UUID primary keys**, generated by the database.
3. **Integer paise** for all INR amounts (`numeric(20,0)`). Never float.
4. **`business_id` on every tenant table**, with RLS.
5. **Append-only ledgers** for audit and stock. No UPDATE, no DELETE.
6. **Explicit status enums**, not free-text status columns.
7. **Idempotency keys** on anything a client can retry.
8. **Separate marketplace orders from receivables invoices.** They are different
   domains and must not share a table.

## 4. Tables

### 4.1 Business capabilities

```sql
create table public.business_capabilities (
  id uuid primary key default gen_random_uuid(),
  business_id uuid not null references public.businesses (id) on delete cascade,
  capability public.business_capability not null,
  is_active boolean not null default true,
  created_at timestamptz not null default now(),
  unique (business_id, capability)
);

create index business_capabilities_business_idx
  on public.business_capabilities (business_id);
```

**Why a join table:** a business can be a supplier and a retailer at once. A
column would force a single role.

### 4.2 Business verification

```sql
create table public.business_verifications (
  id uuid primary key default gen_random_uuid(),
  business_id uuid not null references public.businesses (id) on delete cascade,
  status public.verification_status not null default 'pending',
  submitted_at timestamptz,
  reviewed_at timestamptz,
  reviewed_by uuid references auth.users (id) on delete set null,
  rejection_reason text,
  -- Evidence supplied by the business
  document_urls jsonb not null default '[]'::jsonb,
  -- Result of any external GSTIN check (never a claim of verification)
  gstin_check_result jsonb,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (business_id)
);
```

**Note:** `gstin_check_result` records what an external API returned. It is
**not** a verification claim. Only `status = 'verified'` set by a human reviewer
(or an explicitly authorised automated check) means verified.

### 4.3 Products

```sql
create table public.products (
  id uuid primary key default gen_random_uuid(),
  business_id uuid not null references public.businesses (id) on delete cascade,
  name text not null check (length(trim(name)) between 1 and 200),
  sku text not null check (length(trim(sku)) between 1 and 60),
  description text,
  category text,
  hsn_sac text,
  unit text not null default 'pcs',
  -- Cost is PRIVATE. Never exposed to buyers.
  cost_price_paise numeric(20,0) check (cost_price_paise >= 0),
  tax_rate_basis_points integer not null default 1800
    check (tax_rate_basis_points between 0 and 10000),
  is_active boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (business_id, sku)
);

create index products_business_idx on public.products (business_id);
create index products_category_idx on public.products (category);
```

**`cost_price_paise` is the most sensitive column in the schema.** RLS must
prevent any other tenant from reading it. A separate view exposes the
buyer-safe projection.

### 4.4 Marketplace listings

```sql
create table public.marketplace_listings (
  id uuid primary key default gen_random_uuid(),
  business_id uuid not null references public.businesses (id) on delete cascade,
  product_id uuid not null references public.products (id) on delete cascade,
  status public.listing_status not null default 'draft',
  wholesale_price_paise numeric(20,0) not null check (wholesale_price_paise >= 0),
  min_order_quantity numeric(14,3) not null default 1 check (min_order_quantity > 0),
  delivery_regions text[] not null default '{}',
  available_from date,
  available_until date,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index marketplace_listings_business_idx
  on public.marketplace_listings (business_id);
create index marketplace_listings_status_idx
  on public.marketplace_listings (status) where status = 'active';
```

### 4.5 Price tiers

```sql
create table public.listing_price_tiers (
```

### 4.7 Inventory movements — the ledger

```sql
create table public.inventory_movements (
  id uuid primary key default gen_random_uuid(),
  business_id uuid not null references public.businesses (id) on delete cascade,
  product_id uuid not null references public.products (id) on delete restrict,
  location_id uuid not null references public.inventory_locations (id) on delete restrict,
  movement_type public.movement_type not null,
  quantity_delta numeric(14,3) not null check (quantity_delta <> 0),
  unit text not null,
  -- Link to the originating event
  source_type text,
  source_id uuid,
  -- Snapshot at write time so the ledger is readable without replay
  quantity_before numeric(14,3) not null,
  quantity_after numeric(14,3) not null,
  reason text,
  created_by uuid references auth.users (id) on delete set null,
  created_at timestamptz not null default now()
);

create index inventory_movements_product_idx
  on public.inventory_movements (business_id, product_id, created_at desc);
create index inventory_movements_source_idx
  on public.inventory_movements (source_type, source_id);
```

**Append-only enforced by trigger:**

```sql
create or replace function public.guard_inventory_movement_immutable()
returns trigger language plpgsql as $$
begin
  raise exception 'Inventory movements are append-only and cannot be modified or deleted'
    using errcode = '22023';
end;
$$;

create trigger inventory_movements_guard
  before update or delete on public.inventory_movements
  for each row execute function public.guard_inventory_movement_immutable();
```

## 5. Views

### 5.1 Buyer-safe product view

```sql
create or replace view public.marketplace_product_view
with (security_invoker = true)
as
select
  l.id as listing_id,
  l.business_id as supplier_business_id,
  b.display_name as supplier_name,
  b.state_code as supplier_state,
  p.id as product_id,
  p.name,
  p.sku,
  p.description,
  p.category,
  p.hsn_sac,
  p.unit,
  l.wholesale_price_paise,
  l.min_order_quantity,
  l.delivery_regions,
  l.status
from public.marketplace_listings l
join public.products p on p.id = l.product_id
join public.businesses b on b.id = l.business_id;
-- NOTE: cost_price_paise is deliberately absent.
```

### 5.2 Stock view

```sql
create or replace view public.product_stock
with (security_invoker = true)
as
select
  m.business_id,
  m.product_id,
  m.location_id,
  sum(m.quantity_delta) as on_hand,
  coalesce((
    select sum(r.quantity) from public.stock_reservations r
    where r.product_id = m.product_id
      and r.location_id = m.location_id
      and r.status = 'active'
  ), 0) as reserved
from public.inventory_movements m
group by m.business_id, m.product_id, m.location_id;
```

`available = on_hand - reserved` is computed in the client or a wrapper view.

## 6. RLS policy pattern

Every new tenant table follows the existing pattern:

```sql
alter table public.<table> enable row level security;

create policy <table>_select_member on public.<table>
  for select to authenticated
  using (public.is_business_member(business_id));

create policy <table>_insert_writer on public.<table>
  for insert to authenticated
  with check (public.can_write_financials(business_id));

create policy <table>_update_writer on public.<table>
  for update to authenticated
  using (public.can_write_financials(business_id))
  with check (public.can_write_financials(business_id));
```

**Marketplace-specific exception:** listings must be readable by *other*
verified businesses, not just members.

```sql
create policy marketplace_listings_select_verified on public.marketplace_listings
  for select to authenticated
  using (
    public.is_business_member(business_id)
    or (
      status = 'active'
      and exists (
        select 1 from public.business_verifications v
        where v.business_id = marketplace_listings.business_id
          and v.status = 'verified'
      )
    )
  );
```

This is the **only** place where a tenant table is readable across tenants, and
it is restricted to active listings from verified businesses.

## 8. Data migration risks

| Risk | Severity | Mitigation |
|---|---|---|
| Existing businesses have no capabilities | High | Backfill `buyer` + `seller`, flag for review |
| Existing businesses unverified | High | Backfill `pending`; marketplace gated |
| `cost_price_paise` leakage | **Critical** | Never in buyer-facing views; RLS tested |
| Duplicate stock movements from retried webhooks | High | Unique constraint on provider event id |
| Order/invoice confusion in reports | High | Separate tables, separate report queries |
| Enum extension breaking existing rows | Medium | Additive only |
| RLS policy on listings too permissive | **Critical** | Explicit pgTAP test for cross-tenant listing access |

## 9. What is NOT in this schema

Deliberately excluded until approved:

- Wallet / escrow tables
- Card data (any form)
- Logistics / shipment tracking
- Credit scoring
- Recommendation engine
- Multi-currency
- Consumer accounts

Each would add regulatory or complexity burden without proven need.
